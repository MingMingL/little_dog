## 〇、小白导读（非硬件读者看这里）

**做什么**：喊一声特殊口令（如"小狗过来"），机器狗听出是你的声音、判断你在哪个方向，开到你面前停下，然后跟你聊天。

**三样新东西**：①多装了 3 个麦克风（凑够 4 个才能判断方向）；②加了一个小摄像头（最后几米用眼睛确认"面前是你"，防止对着电视/别人乱停）；③软件上新写"召唤模式"（优先级最高，你一喊它，巡逻/看门都让位）。

**一句话边界**：同一个房间、互相看得见，基本保证开到身边；隔着墙是"试着找"，不打包票。完整通俗解释见可行性方案 v0.4 的"小白导读"。

## 3. 硬件改动与引脚分配（最终版）

### 3.1 三处硬件改动

1. **加麦克风阵列**：新增 3× INMP441，与现有麦克风组成 4 麦方阵；共享 SCK/WS（GPIO4/5），每麦独立 SD 数据线（GPIO6 现有 + 38/39/40 新增）。
2. **巡线改 I²C**：5 路 TCRT5000 输出从 GPIO17/18/38/39/40 改接到 PCF8574（P0–P4），PCF8574 挂现有 I²C（GPIO41/42，与 VL53L0X 0x29 并联）；固件中巡线读取从 GPIO 改为 I²C 读 8 位。
3. **OLED CS 飞线**：把 OLED 模块上"CS 接 GND"的跳线切断，焊一根飞线到 **GPIO45**；固件 `DISPLAY_CS_PIN` 由 `GPIO_NUM_NC` 改为 `GPIO_NUM_45`。

> **GPIO45 注意**：它是 strapping 脚，上电时电平决定启动模式——飞线时按 ESP32-S3 启动要求加合适上/下拉（通常保持高电平即可正常启动，以数据手册为准），启动后可正常当 GPIO。**若不愿动 strapping 脚**，用备选：OLED CS 仍接 GND，摄像头每次用完后由固件重新初始化 OLED（软件兜底，召唤过程中屏幕会闪一下，可接受）。

### 3.3 4 麦采集的电气实现（固件侧择优，不改硬件）

三种接法均可由上述引脚支持，按 ESP-IDF v6.1 实测择优（M1 阶段定）：
- **(a) 每麦独立 SD 线**（本方案默认设计）：4 路数据，I²S 多数据线/TDM 方式采集；
- **(b) 双麦共享一条 SD**（L/R 分槽）×2：只占 2 条数据线，富余 GPIO 备用；
- **(c) 换成品 TDM 阵列板**（4 麦合成 1–2 路 I²S）：引脚最省，阵列板 ¥40–80。

### 4.2 Summon 状态机

```
[任意模式] --唤醒词命中--> [S1 口令验证 1.5~3s] --通过--> [S2 SUMMON]
S2 循环（停-听-走，结构上规避电机自噪）:
  听 0.5s（DOA+能量，多帧滤波）→ 原地对准（比例伺服，死区 ±12°，点动防过冲）
  → 前进 1.5s（低速）→ 停 → 听 → 重定向 …
  避障：VL53L0X < 0.4m → 停车 → 侧向绕行或原地重定向
  接近段触发（DOA 稳定 + 能量进入近场特征区）→ 启摄像头
S3 视觉确认：抓 1~2 帧 JPEG → 人形检测
  → 有人形 → S4 到达
  → 无人形 → 回 S2（最多 3 次）→ 仍无 → S5 降级
S4 到达：停车 → 狗叫/问候 → 自动切 Chat
S5 降级：原地 360° 扫描重搜一次 → 仍失败 → 回 Idle，App 提示"没找到你"
异常：超时（60s）/ 声源丢失 → 同 S5
```

## 7. 风险登记与降级路径（每条都给"不过怎么办"）

| 编号 | 风险 | 不过怎么办（按顺序尝试） |
|---|---|---|
| R-F1 | 电机自噪淹没麦克风 | 隔振/双绞/磁环 → PWM ≥20kHz（哼声移出语音/DOA 频带）→ AFE NSNet2 辅助（仅唤醒/ASR 链路）→ 停-听-走占空比降至 30% → 本期只承诺"原地转向 + 短距（≤2m）接近" |
| R-F2 | 4 麦 I²S 采集方式在 IDF 上不顺 | (a)→(b)→(c) 三种电气实现切换（§3.3），不改硬件 |
| R-F3 | DOA 精度不达标 | 多帧滤波/频带调优 → 只承诺大角度粗定向 → 评估路线 A/方案二（见 v0.4） |
| R-F4 | GPIO45 上电电平导致启动异常 | 加上/下拉满足启动模式 → 改 GPIO3 → 软件兜底（摄像头用后重初始化 OLED） |
| R-F5 | ArduCAM 初始化失败 | RESET 静态接高无效时，RESET 改接可控 GPIO（与 OLED CS 方案二选一） |
| R-F6 | 人形检测慢/误检 | 降分辨率 160×120、只抓 1 帧、调阈值 → 仍不过则关闭视觉，退回纯声学到达判定（AT-S04 口径），摄像头留待路线 A |
| R-F7 | SPI 总线冲突（T2 失败） | OLED CS 飞线方案排查虚焊 → 改软件兜底 |
| R-F8 | PCF8574 读巡线不稳 | 模块端加 10k 上拉 → 降轮询速率 → 暂时只用于巡逻（巡线本来就不在 Summon 用） |
| R-F9 | 口令被误触发/漏触发 | 换更长口令 → 降唤醒灵敏度 → 提前上 L2 声纹 |
| R-F10 | 看门模式被召唤词打断（安全悖论） | 口令通过才进 Summon；App 提供"看门时段禁用召唤"开关 |

## 8. 实施阶段（不含工期估算）

1. **M0 物料与引脚确认**：采购 §2 清单；点灯实测 GPIO22–25 可用性；确认 GPIO45 上电电平；确认 TB6612 与电机参数（沿用 V1 M0 结论）。
2. **M1 音频链路**：阵列焊接 → 4 麦采集（§3.3 择优）→ DOA 定向 → 自噪抑制调试；通过 T3/T4。
3. **M2 唤醒 + 状态机 + 运动**：唤醒词/口令 → Summon 状态机 → 停-听-走导航 → VL53L0X 避障；通过 T5、AT-S03/04/05/07/08。
4. **M3 视觉融合**：ArduCAM 抓帧 → 人形检测 → 到达判定融合；通过 T2/T6、AT-S09。
5. **M4 整机与 App**：Android 适配、巡线/显示回归（AT-S10/11）、AT-S01~S09 全量验收、日志与文档归档。

## 9. 遗留与备选（均指向可行性方案 v0.4）

- 路线 A（DVP 连续视觉）、方案二（ESP32-S31 整机）、UWB 精确定位：保留在 v0.4，本期不实施；触发条件见 §1.2。
