## 小白导读（不懂技术也能看）

**召唤功能是干什么的**：你站在屋里喊一声特殊口令（比如"小狗过来"），机器狗听出是你的声音，就开到你面前停下，然后跟你聊天。

**它靠三个本事做到：**

1. **听出是你**：就像朋友听脚步声就知道是你——机器狗先听口令，再辨认声音特点，确认是你才动（防止别人一喊就跟着跑）。
2. **听出你在哪**：狗身上有 4 个麦克风**围成一圈**（不是排成一排）。声音传到 4 只耳朵有先有后，就能算出你大致在哪个方向。围成一圈是为了分得清前后——排成一排会分不清你在它前面还是后面（术语叫"前后模糊"）。
3. **开到你面前**：
   - **不在一条直线上根本不是问题**：狗是两轮驱动，能原地转圈——听到你在哪边就转向哪边，对准了再开。你在它左边、身后、斜对面都一样。
   - **它自己走路有噪音**：电机声会盖住你的声音，所以走几步 → 停下来 → 听一下 → 修正方向 → 再走（就像走在嘈杂的街上要停下来才听清朋友在哪个方向喊你）。代价是慢一半左右，但听得准。
   - **它不知道你离多远**，只知道方向：所以"到了没有"靠几个迹象一起判断（破案式）——你的声音明显变大了 / 你就在正前方且测到了"一个人形状的障碍" / 走的时间太长（如 60 秒）就放弃。满足任一条件就停车、狗叫一声、切聊天。
   - **隔墙或拐角后面，不敢保证**：声音会绕墙，狗可能对着一堵墙开。对策是贴墙绕行，每走一小段停下来听一次——声音变大、方向变清楚=绕对了；声音变小=换另一边。实在找不到就报告"找不到路"，不硬闯。
   - **想要最后几米更稳**：加个摄像头，最后几米用眼睛看人比用耳朵靠谱（直接开过去停你面前）。
   - **要求隔墙也必须找到**：加 UWB（相当于给狗和你各配一个室内定位信标，像室内 GPS），不靠声音、随时知道你在哪——但要额外花钱，列为可选。

**一句话边界**：同一个房间、互相看得见，基本保证开到身边；隔着墙，是"试着找"，不打包票。

**两个方案的大白话区别**：
- **方案一（升级）**：还是现在这只狗——加耳朵（多几个麦克风）、加隔振、软件上新写"召唤模式"。花钱少（一百多块），先把功能跑起来试水。
- **方案二（重做）**：换一匹更强的狗——换大脑（ESP32-S31，算力更强、定位更准）、换腿（带编码器的底盘，走得准）、可选加眼睛（摄像头）。花钱多（整机五百到七百五），但定位和行驶都更稳。

## 0. 30 秒结论

- **需求三句话的工程本质：** ①自定义唤醒词 + 说话人验证 → ②麦克风阵列声源定位（DOA）+ 无地图寻声导航 → ③状态机新增最高优先级模式。**最大硬件缺口是"单麦克风"**——现有 ai-dog-s3 板只有 1 路 INMP441，做不了声源定位，必须增麦。
- **方案一（现有项目升级）**：保留 ESP32-S3 与 xiaozhi 固件基座，增加 3 路麦克风组成 4 麦阵列（增量约 **¥100–180**），软件新增 Summon 模式。**最快验证、风险最低**，但 S3 算力与 GPIO 紧张，DOA 精度与自噪抑制是主要考验。摄像头可按 §3.6 分两档叠加：快照确认约 **+¥60–80**（零引脚冲突），连续视觉伺服约 **+¥20–30** 但要动 GPIO 改造。
- **方案二（重新设计）**：主控升级 **ESP32-S31**（同 ESP-IDF 生态、官方 DOA 支持、Wi-Fi 6、算力约为 S3 的 1.65 倍），自研大孔径 4 麦圆阵，底盘升级为编码器 4WD/大轮 2WD，可选摄像头做视觉确认。整机约 **¥550–750**，性能与扩展性最好，但等于重新做一遍硬件。
- **建议路径：** 先用方案一的"最小可验子集"（唤醒词 + 声音口令 + 4 麦 DOA 寻声）跑通三件事——误唤醒率、DOA 精度、电机自噪抑制；验证成立后，V2 按方案二升级主板（软件基本可平移，因为本项目固件已内置 ESP32-S31 板级支持）。

## 1. 需求工程化拆解

| 用户原话 | 工程化定义 | 编号 |
|---|---|---|
| 特殊唤醒词 + 声纹识别，切换到召唤模式 | 任意模式下后台监听自定义唤醒词；命中后进行说话人验证；通过则切入 Summon 模式 | FR-S1 |
| 声音定位召唤者位置，自动行驶到召唤者处并切聊天模式 | 多麦克风声源定向（DOA）→ 朝声源寻声行驶（避障 + 停-听-走）→ 到达判定 → 自动进入 Chat 模式 | FR-S2 |
| 召唤模式优先级高于其他模式 | Summon 为抢占式最高优先级模式（仅物理急停高于它）；运行期间拒绝 App 普通模式切换 | FR-S3 |

由此派生 6 个技术问题：

| 编号 | 技术问题 | 现状 | 召唤功能要求 |
|---|---|---|---|
| T1 | 自定义唤醒词 | xiaozhi 已集成 ESP-SR WakeNet | 定制"小狗过来"类唤醒词，全模式后台监听 |
| T2 | 声纹/说话人验证 | 无 | 端侧或云端说话人验证，防陌生人误召 |
| T3 | 声源定位 DOA | **单麦克风，原理上不可行** | ≥2 麦（建议 4 麦圆阵/方阵），输出 0–360° 角度 |
| T4 | 寻声导航 | 仅有循线巡逻（依赖地面标线） | 无地图：DOA 伺服 + 差速转向 + 避障 + 自噪抑制 |
| T5 | 模式状态机 | 5 模式（idle/chat/patrol/guard/remote） | 新增 Summon，抢占逻辑 |
| T6 | 到达判定与自动切聊天 | 无 | 声源距离粗估 + 超时保护 → 切 Chat |

### 1.1 关键调研结论（2026-10 核实）

1. **唤醒词可行。** ESP-SR WakeNet9 支持自定义唤醒词（乐鑫定制服务或 TTS 样本训练），本项目固件（xiaozhi-esp32）已内置 AFE + WakeNet 全链路，S3/P4/S31 均支持唤醒词模型。
2. **DOA 有官方方案但分平台。** 乐鑫官方 Capon DOA 模块（10° 分辨率、2–8 麦任意阵型）目前仅支持 **ESP32-P4 / ESP32-S31**；但组件 `esp_apa_doa`（v1.0.0）**支持 ESP32-S3**（2–4 麦，共线/三角/方阵/长方阵），可作为 S3 上的降级路径。
3. **声纹无官方 ESP-SR 支持，需自建或上云。** 端侧路线：x-vector 轻量模型（嵌入向量约 80–200KB）+ 余弦相似度比对，S3 上可跑但需实测耗时；云端路线：3D-Speaker（开源）自建或阿里云/讯飞声纹 API，精度高但依赖网络。
4. **ESP32-S31 已量产且本固件已支持。** RISC-V 双核 320 MHz（约 2,195 CoreMark，S3 约 1,330）、Wi-Fi 6、SIMD/FPU、60 GPIO、512KB SRAM；xiaozhi-esp32 仓库已内置 `esp32-s31-korvo-1` 等 S31 板级，ESP-IDF v6.1（本项目当前版本）即可构建。**这是方案二软件复用率高的关键依据。**
5. **ESP32-P4 无线缺失。** P4 无内置 Wi-Fi/蓝牙，需配 ESP32-C6/C5 协处理器，BOM 与软件复杂度上升；其价值在 MIPI-CSI 摄像头 + H.264，适合"视觉召唤"变体，不作为主线推荐。

## 3. 方案一：在现有项目基础上升级

### 3.1 总体思路

- **硬件做最小增量**：单麦 → 4 麦阵列；麦克风机械隔振；电机线抗干扰；前向避障补强（可选超声）。

- **语音聊天链路完全复用** xiaozhi 云端（到达后自动切 Chat，无新链路开发）。

### 3.4 召唤流程设计（无里程计也能工作）

```
[任意模式] --唤醒词命中--> [声纹验证 1.5~3s] --通过--> [SUMMON]
SUMMON 循环（停-听-走交替，结构上规避自噪）:
  听 0.5s（DOA + 能量）→ 转向伺服（差速点动，直到 DOA 报"声源在正前方 ±15°"）
  → 前进 1.5s（低速）→ 停 → 听 → 重新定向 → 前进 ...
  避障：ToF/超声 < 阈值 → 停车 → 侧向绕行或原地重新定位
到达判定（任一满足）:
  ① 声源能量进入近距离特征区且 DOA 连续多帧不稳定（近场效应）
  ② 行驶计时达到上限（如 60s）
  ③ 前向 ToF 测到稳定"人体尺寸"遮挡且 DOA 指向正前
→ 停车 → 狗叫/问候语 → 自动切 Chat 模式
异常：超时未到达 / 声源丢失 → 原地旋转扫描（360°）→ 仍失败 → 回 Idle 并 App 提示
```

要点：
- **不依赖编码器与地图**：导航是"相对伺服"——把 DOA 角度误差转向 0 即对准，与机器狗自身朝向无关，省掉航向推算与 SLAM。
- **停-听-走**是自噪抑制的核心手段：电机停转时监听，DOA 估计不受自噪污染；代价是移动速度为巡航的 50% 左右。

#### 3.4.1 召唤者不在正前方/直线上时，如何保证准确到达

**先分类，"不在一条直线上"其实是两种情况，保证手段完全不同：**

| 情况 | 描述 | 能否保证 | 手段 |
|---|---|---|---|
| 情况 1：偏离轴线但**视线可达** | 人在侧面、斜前方、身后（DOA 报 30°/120°/270° 等） | **能保证**（同房间） | 原地转向伺服 + 停-听-走重定向（见下） |
| 情况 2：**被遮挡/非视距** | 拐角、家具后、另一房间（DOA 指向墙或反射面） | **不能保证**，只能尝试性接近 | 沿障绕行 + 周期性重听 + 视觉/状态降级（见下） |

**情况 1 的保证手段（感知 + 控制闭环，四层）：**

1. **阵型上消除前后模糊**：4 麦方阵/圆阵在平面内 360° 无前后混淆（线阵才有 180° 模糊），身后 180° 也能给出确定方向；2WD 差速底盘可原地旋转，DOA 报多少度就原地转多少度，不存在"转不过去"的几何问题。
2. **原地对准闭环**：转向角速度 ∝ DOA 误差（比例控制，死区 ±10~15°，差速点动防过冲）；MPU6050 角速度辅助防过冲；对准（误差进死区）才允许前进，边前进边每周期复核 DOA，偏差超阈值立即停车重对准——防止"斜着漂"。
3. **干净的感知输入**：DOA 每 8ms 一帧，取多帧中值/卡尔曼滤波去野值；关键定向都放在"停车听"窗口内做（自噪归零），行驶中 DOA 仅作趋势参考。
4. **距离未知 → 多重停止条件 OR 判决**（DOA 只有角度没有距离，用弱特征组合补）：
   - 声能量进入近场特征区（标定值）且 DOA 连续多帧方差变大（近场效应）；
   - 前向 ToF 正前方稳定人体尺寸遮挡，且 DOA 指向正前 ±30°；
   - 行驶计时/里程上限（开环保护，如 60s）；
   - 有摄像头时：视觉人形框占比达阈值 → 视觉伺服接管最后 1–2m（单目框高 ∝ 1/距离，标定后粗估）。

**情况 2 的保证手段（绕障 + 重听 + 诚实降级）：**

1. 前向 ToF/超声 < 阈值 → 停车但保持监听；
2. **沿障绕行**：择一侧贴障绕行，绕行中每 0.5–1m 停车重听 DOA 与能量；
3. **通道检测**：绕行后若 DOA 误差变小且能量变大 → 方向正确，继续；误差变大或能量变小 → 回退换另一侧；
4. **超时/能量持续衰减 → 主动降级**：判定"声源当前不可达"，App 明示"找不到路"并回 Idle，不承诺跨房间必达；
5. **摄像头是跨遮挡唯一"硬保证"的最后段**：视线恢复（看到人形）后由视觉伺服接管最后 1–2m，声学段只负责把机器狗带到视线口；摄像头放在头部、视场角覆盖正前 ±40° 即可满足该用途。

**边界声明（建议写入正式 PRD 与验收）：**

- 同房间、视线可达：承诺 5m 内 10 次 ≥7 次到达召唤者 1m 圈内（AT-S04）；
- 遮挡/跨房间：只承诺"朝声源方向尝试移动 + App 状态可见"，**不保证到达**；
- 若要"跨房间也保证到达"，需要超越声学的定位手段：最便宜的精确位置方案是 **UWB**（tag 约 ¥30–60 + 2–4 个锚点，10–30cm 精度，不依赖声传播路径与视线），但这超出"声音定位"的需求定义，列为可选升级项，不进主线。
- **看门模式的相互影响**：Summon 可抢占 Guard，但陌生人说唤醒词会让狗离开看守位。缓解：声纹验证通过才真正进入 Summon（L1 档只有口令、无认人能力，需在 App 明示风险），或配置"看门时段禁用召唤"。

### 3.5 方案一优缺点

**优点**
- 复用全部现有资产：固件基座、状态机、HTTP API、Android App、接线文档、调试脚本；无重新流片/打样主控板。
- 增量成本低（约 ¥115–180），硬件改动集中在"增麦 + 隔振"，不动电源与主控。
- 风险隔离性好：召唤功能可做成编译开关/独立模式，不影响 V1 已验证的聊天与看门。
- 最快拿到"能不能用"的真实数据（误唤醒率、DOA 精度、自噪水平），为 V2 决策提供依据。

**缺点**
- **算力天花板**：S3 上 AFE + WakeNet + DOA + 声纹 + 电机控制并发，需精心做任务分级（如监听期降 ASR 缓冲、声纹只在唤醒后跑）；极限场景可能掉帧/延迟。
- **DOA 精度受限**：4–5cm 小孔径阵列 + S3 上非官方 DOA 实现，角度误差与更新率都弱于官方 Capon 模块；混响环境衰减明显。
- **GPIO 紧张**：新增 3 路麦克风数据线需要重排引脚（现板仅剩 4 个安全脚），可能要改板走线或加小板转接。
- 摄像头需额外评估（§3.6）：快照档（SPI，+¥60–80）便宜且零引脚冲突但只能做到达确认；连续伺服档（DVP，+¥20–30）要动 GPIO 改造且与音频抢算力。
- 单麦→4 麦的 I²S 改造要动 `ai_dog_s3_board.cc` 音频初始化（现有是 Simplex 单麦配置）。

### 3.6 加装摄像头（视觉能力）扩展评估

**结论先行：能加。** ESP32-S3 自带 DVP 并行摄像头接口，可接 OV2640/GC0308 类模组；人形/人脸检测用 ESP-WHO / ESP-DL（S3 原生支持）。但"要不要加、加哪一档"取决于让视觉干什么——按价值排序：

| 视觉用途 | 价值 | 需要档位 |
|---|---|---|
| **到达确认**（面前是不是真人） | **高**：根治"电视人声/旁人说话/音响外放"导致误停 | 快照即可（路线 B） |
| **视觉伺服**（用人形框替代/校正 DOA 方向） | 高：根治 DOA 在混响/多声源/自噪下不可靠 | 连续推理（路线 A），算力吃紧 |
| 中途低矮/透明障碍补强 | 中 | 连续推理，S3 上性价比一般（前向 ToF/超声已覆盖大半） |
| 人脸/人形身份确认（替代声纹） | 低 | 不推荐：与声纹重复建设，隐私代价大 |

#### 路线 A：DVP 摄像头 + 连续视觉（+¥20–30 器件，含 GPIO 改造）

- **器件**：OV2640/GC0308 24P DVP 模组（选板载 LDO、3.3V I/O 的版本）；SCCB（摄像头配置总线）复用现有 I²C（GPIO41/42）。
- **引脚问题（本路线真正的难点）**：S3 的 esp_camera 需要 XCLK/PCLK/VSYNC + D0–D7 共 **11 个 GPIO**，而本板 GPIO 已枯竭（config.h 中仅剩 GPIO1/2/46/48 安全脚）。解决办法（组合使用）：
  1. **巡线 5 路（GPIO17/18/38/39/40）挪到一片 PCF8574 I²C 扩展**（+¥5）：永久释放 5 个脚，且巡线功能完全不受影响（数字量传感器，I²C 轮询速率足够）；
  2. **OLED 的 4 脚（GPIO1/2/46/48）在 Summon 期间动态让位**：进入 Summon 关屏、退出恢复显示（OLED 只是状态显示，召唤过程很短，可接受）；
  3. **TB6612 STBY（GPIO10）硬件跳线硬接 3.3V**：释放 1 脚（STBY 常有效，符合"电机随时可停"的安全设计，急停改由 PWM 归零实现）；
  4. **仍差 1 脚**：用 GPIO3/45 等 strapping 脚在运行期作 GPIO（保证上电时电平符合启动模式即可），或让电池 ADC 在 Summon 期间暂停采样（改为进入 Summon 前做一次低电量预检）。
- **能力**：QQVGA/QVGA 人形检测约 3–8 FPS（以实测为准），可与 DOA 融合做粗粒度视觉伺服（视觉管目标方位、DOA 管声源确认与初始对准）。
- **代价**：飞线改板 + 与音频链路抢算力（见 R-S10）。

#### 路线 B：SPI 摄像头 + 快照确认（+¥60–80 器件，零引脚改造）

- **器件**：ArduCAM Mini 2MP Plus 类 SPI 摄像头（JPEG 输出，3.3V）。
- **引脚**：与 OLED **共享 SPI 总线**（SCK=GPIO1、MOSI=GPIO2），只需再占 MISO/CS 两个 GPIO——正好用上面第 1 步释放的 GPIO17/18。**OLED 与巡线都不用动，零动态复用。**
- **能力**：到达判定前 2–3 秒抓 1–2 帧，本地跑人形检测，确认"面前有人"才停车切聊天。SPI 带宽不支持连续视觉伺服。
- **适用**：以最小改造先击穿"误到达"这个最痛的击点；后续若确需连续伺服，再按路线 A 升级（或直接上方案二）。

#### 算力与结构注意

- **视觉只在"接近段/到达段"开启**：DOA 稳定且声源能量进入近场特征区后再启动摄像头与推理，全程不跑；DOA、唤醒、声纹不受影响。
- 摄像头建议与麦克风阵列同区布置（头部），但 DVP 是高速并行总线：走线等长、远离电机线、长度尽量短（建议 <15cm）。
- **隐私与 V1 PRD 一致**：不存图、不上传、只做人形存在性判定；App 明示摄像头仅在召唤接近段工作；非召唤时段摄像头断电（用 PWDN 或模组电源控制）。

#### 对方案对比的影响

叠加路线 B 后，方案一也具备"视觉确认"，方案二独有的优势收缩为：**连续视觉伺服的算力余量、官方 Capon DOA、编码器闭环底盘**。换言之：

- 若实测发现"误到达"是主要痛点 → 先加路线 B（便宜、改动小）；
- 若实测发现"DOA 不可靠、必须连续跟踪人形" → 瓶颈是算力与定位精度，不要再往 S3 上堆视觉，直接按方案二升级。

## 4. 方案二：重新设计（硬件 + 软件）

### 4.1 总体思路

- **主控升级 ESP32-S31**：算力约 1.65×、Wi-Fi 6、60 GPIO、SIMD/FPU，且**官方 Capon DOA 模块支持**；与 ESP-IDF v6.1 + xiaozhi 固件同生态（仓库已内置 S31 板级，语音链路可平移）。
- **自研 4 麦圆阵小板**：孔径加大到 8cm 级，角度分辨率与鲁棒性显著优于小阵列；阵列独立成板，与主控板解耦。
- **底盘升级**：4WD 或大轮径 2WD + 编码器 + 独立悬挂，越障（门槛/地毯）与短距精控能力提升；电机换低噪型号。
- **可选摄像头**：DVP 接口接 GC0308/OV2640 类模组，做"最终接近段视觉确认"（看到人再停），降低纯声学误判定；视觉模型支持度需实测（ESP-DL 对 S31 的支持以官方文档为准，不满足则退化为"画面供云端/人工查看"或选 ESP32-P4 变体）。
- **软件服务化重写**：音频、召唤、导航、聊天四个服务 + OTA + 完整日志；语音聊天仍走 xiaozhi 云端。

**备选平台说明（不推荐作主线）**：Rockchip RV1106/RV1103（Linux + NPU）算力与生态更强，但意味着放弃 ESP-IDF 实时性与整个 xiaozhi 固件基座，软件全重写、周期与风险不可控，仅在"必须做视觉人物跟随 + 本地 ASR"时再评估。

### 4.4 方案二优缺点

**优点**
- 算力与 GPIO 宽裕：DOA + AFE + 声纹 + 视觉可以真正并发，不用互相降载。
- 官方 Capon DOA + 大孔径阵列：定位精度、更新率、抗混响能力都是方案一的上位替代。
- 编码器底盘 + 双侧避障：寻声行驶更稳，可跨越简单门槛/地毯，室内适应面更广。
- 摄像头提供"第二眼睛"：纯声学误判（电视人声、他人说话）可用视觉确认过滤。
- 单芯片 Wi-Fi 6 + 更多外设余量，为后续功能（本地 ASR、表情屏、自动回充）留足空间。

**缺点**
- **整机重做**：主板、底盘、电源、结构全部重新设计打样，硬件周期与调试量接近重走一遍 V1。
- 成本更高（整机 ¥510–750，且 S31 模组供货与价格尚在爬坡，需询价锁定）。
- 新平台 bring-up 风险：S31 生态较新（ESP-IDF v6.1 才完善支持），xiaozhi 对 S31 的板级虽已内置，但麦克风阵列/多通道音频路径需要自行验证。
- 摄像头视觉管线（ESP-DL 对 S31 的支持）存在不确定性，可能退化为纯声学方案，届时视觉投入沉没。
- Android App 与 HTTP 协议需适配新状态字段（工作量小但非零）。

## 6. 决策建议

**推荐"先方案一最小子集验证，再按方案二要素演进"的混合路线：**

1. **第一阶段（方案一子集）**：只做"自定义唤醒词 + L1 声音口令 + 4 麦 DOA + 停-听-走寻声"，硬件只增麦和隔振。目标是拿到三个实测数：唤醒词误唤醒率（安静环境 30min ≤1 次）、DOA 角度误差（1–3m 内 ±30° 命中率）、行驶中自噪对 DOA 的污染程度。**这三项决定方案二值不值得做。**
2. **第二阶段（方案一补全）**：按实测结果补 L2 端侧声纹或 L3 云端声纹；完成到达判定标定与 App 适配；通过 AT-S01~S07。**若实测发现"误到达"（对电视声/旁人停车）是主要痛点，优先叠加路线 B 快照视觉（+¥60–80，只占 2 个 GPIO）；若发现"DOA 不可靠、必须连续跟踪人形"，说明瓶颈在算力与定位精度，不要再往 S3 上堆视觉，直接按方案二升级（连续视觉伺服是方案二的主场）。**
3. **第三阶段（方案二升级）**：若 DOA 精度或自噪成为明确瓶颈，再上 S31 + 大孔径阵列 + 编码器底盘；此时软件框架已在方案一验证，主要是板级移植与导航精度提升。

若预算与时间极紧，可在第一阶段就引入方案二的两个"便宜要素"：**低噪电机 + 麦克风隔振结构**（合计不到 ¥30），它们对两个方案都是纯增益。

## 7. 风险与开放问题

| 编号 | 风险/问题 | 等级 | 影响 | 应对原则 |
|---|---|---|---|---|
| R-S1 | **电机自噪淹没麦克风**（最大风险） | 高 | 行驶中 DOA/唤醒全部失灵 | 隔振 + 电机线双绞/磁环 + PWM ≥20kHz + 停-听-走 + DOA 频带滤波；实测不达标则降低移动占空比 |
| R-S2 | S3 并发算力不足（AFE+WN9+DOA+声纹） | 高 | 延迟、丢帧、唤醒漏检 | 任务分级；声纹仅唤醒后运行；必要时声纹上云（L3） |
| R-S3 | DOA 精度受阵列孔径/混响/多声源影响 | 中 | 定位偏差、寻声绕路 | 方案一用小孔径需降低期望；方案二用 8cm 孔径；多源场景以能量+DOA 稳定性融合判断 |
| R-S4 | 声纹误识/拒识；录音回放攻击 | 中 | 陌生人误召 / 主人拒识 | 文本相关口令（L1）+ 活体提示（随机口令）；阈值可调；不承诺安防级 |
| R-S5 | 看门模式被召唤词打断的安全悖论 | 中 | 狗离开看守位 | 声纹通过才进 Summon；可配置"看门时段禁用召唤"；App 明示 |
| R-S6 | 到达判定误判（电视声/他人说话） | 中 | 停错位置或不停 | 能量近场特征 + DOA 不稳定度 + ToF 联合判定；方案二加视觉确认 |
| R-S7 | S31 生态新（ESP-IDF v6.1 才完善） | 中 | bring-up 周期不可控 | 先买开发板验证音频多通道 + DOA demo，再决定整机投板 |

| R-S9 | S31 模组供货/价格爬坡 | 低 | 成本上浮 | 开发板先验证；量产前锁定模组渠道价 |
| R-S10 | 视觉与音频链路抢 S3 算力/总线（路线 A） | 中 | 推理掉帧、唤醒延迟、I²S 欠载 | 视觉仅接近段开启、3–8 FPS 降频运行、双核分工（音频+视觉 / 电机+网络）；不达标退回路线 B |
| R-S11 | GPIO 改造（巡线挪扩展器、OLED/STBY 让位）引入新故障 | 中 | 巡线失灵、黑屏、电机异常 | 逐项回归测试（巡线/显示/急停/低电量）；改造留在洞洞板，可回拨 |
| Q-S1 | 声纹档位选 L1/L2/L3？ | — | 影响成本与隐私 | 建议先 L1 跑通，按安全诉求再升 |
| Q-S2 | 召唤有效距离目标（5m？8m？）与超时上限 | — | 影响验收阈值 | 第一阶段实测后定 |

## 8. 验收标准建议（召唤功能，V1.5）

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AT-S01 | 唤醒词 | 安静环境 10 次唤醒 ≥9 命中；30min 误唤醒 ≤1 次 |
| AT-S02 | 声纹 | 注册用户 20 次 ≥18 通过；未注册者 20 次误通过 ≤2 次（按所选档位标注） |
| AT-S03 | DOA 定向 | 1–3m 圆周 8 方位测试，角度误差 ≤30° 占比 ≥80% |
| AT-S04 | 寻声行驶 | 5m 直线召唤 10 次，≥7 次在上限时间内到达召唤者 1m 内；全程不碰撞障碍 |
| AT-S05 | 模式优先级 | 巡逻/看门/遥控中被唤醒词打断，≤2s 进入验证流程；Summon 期间 App 普通模式指令被拒、急停始终有效 |
| AT-S06 | 到达切聊天 | 到达后自动进入 Chat 并播报问候，成功率 ≥9/10 |
| AT-S07 | 自触发抑制 | 狗叫播放、聊天播报、自身行驶噪声不触发新的唤醒/召唤 |
| AT-S08 | 异常恢复 | 超时未到达/声源丢失后进入扫描重搜，仍失败则安全回 Idle 并 App 可见；全程不失控行驶 |
| AT-S09 | 视觉确认（选视觉档时） | 到达段抓帧人形检测：对真人在场 10 次 ≥9 确认、对电视人声/空椅 10 次误确认 ≤2；全程不存储、不上传图像 |
