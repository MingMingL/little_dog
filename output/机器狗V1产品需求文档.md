## 评审摘要（30 秒结论）

- **做什么：** 2WD 轮式狗形原型，提供固定路线循线巡逻（遇障停车）、本地声音触发狗叫告警、云端语音聊天三类能力。
- **不做什么：** 不做 SLAM/自由地图导航、四足步行、自动回充，也不做门外声源定位或认证级安防。
- **硬件目标：** 约 ¥500，估算值；预算表合计约 ¥492，仅约 ¥8 机动空间。
- **最大风险：** 电机堵转电流、驱动板连续电流、2S 电池化学体系/BMS/充电器尚未核实 —— 这三项定稿前不建议下单。
- **必须澄清的边界：** 单麦克风只能判断声音强度，不等于「声音来自门外」；本原型不替代门磁或经认证的安防产品。

## 1. 产品概述

本项目拟制作一台面向家庭室内场景的低成本轮式机器狗原型，提供语音聊天、沿预设路线巡逻，以及在门口听到明显声音后播放狗叫警报三类能力。首版以 ESP32-S3 为设备主控，使用家庭 Wi‑Fi 连接云端语音服务；声音检测、模式判断、运动控制和报警播放尽可能留在本机，使看门报警不因外网中断而失效。

**V1 的自动巡逻定义为“循地面标线沿固定路线行走，检测到障碍后停车”**，不包含室内建图、定位到任意目标点、SLAM 或自主绕行。机器狗在看门模式下应停留在靠近入口的位置；单麦克风只能判断声音强度/特征，不能可靠证明声音来自门外，也不承诺识别或区分门铃、敲门、脚步和室内噪声。

硬件预算目标约 ¥500，作为原型采购控制线，不是已锁定的供应商报价。云端 ASR/LLM/TTS 使用费、服务端费用以及已有电脑、手机不计入该硬件预算。

## 2. 用户问题与目标

### 2.1 用户问题

- 希望以较低成本获得一台能移动、能说话且有“狗”外观的家庭机器人原型。
- 希望机器能按简单固定路线巡逻，并在撞上家具前停下。
- 希望离家或夜间时有声音提醒，但无需购买摄像头或完整智能安防系统。
- 希望可以与设备进行自然语言语音对话，而不要求设备端运行大型语音/语言模型。

### 2.2 V1 产品目标

1. 用户可通过设备按键或 Android 控制端切换聊天、巡逻、看门模式。
2. 巡逻模式下沿预先铺设的地面标线行走；检测到前方障碍后停止并提示。
3. 看门模式下在本地检测明显声音并播放预置狗叫音频；无网络时该流程仍可工作。
4. 聊天模式下通过 Wi‑Fi 使用云端语音识别、对话模型和语音合成，并从机器狗扬声器播放回复。
5. 在包含开发板、电源、基础调试材料和 3D 打印外壳的前提下，硬件采购尽量不超过 ¥500。

## 3. 用户与使用场景

### 3.1 用户

- **家庭用户/项目所有者：** 设置看门时段、启停巡逻、与机器狗聊天并进行日常维护。
- **开发与调试者：** 通过串口日志、状态页和手动控制检查传感器、电机与电源。

### 3.2 核心场景

| 场景 | 前置条件 | 期望结果 |
|---|---|---|
| 夜间看门 | 机器狗放置在玄关附近，已设防 | 检测到达到阈值的声音后，在本地播放狗叫；不依赖外网 |
| 离家看门 | 用户在 App 手动设防；V1 可另设计划时段 | 持续监听并在触发后本地报警；用户可在回家后撤防 |
| 固定路线巡逻 | 已铺设并标定地面路线，路径无大台阶 | 机器狗循线移动，前方有障碍时停车 |
| 语音聊天 | Wi‑Fi 和已配置的云端语音服务可用 | 用户发起一轮语音输入，设备播放云端生成的语音回复 |
| 网络中断 | 已进入看门模式 | 本地看门与狗叫可用；聊天显示/播报网络不可用，不导致设备崩溃 |
| 电量不足 | 电池接近低压保护阈值 | 停止移动，播放或显示低电量提示；禁止继续反复启动电机 |

## 4. 产品范围与模式

V1 采用互斥模式，避免巡逻移动时把移动噪声误当成入口声音，也避免聊天播报触发声音报警。

| 模式 | 设备行为 | 网络依赖 | 退出方式 |
|---|---|---|---|
| 待机 | 电机关闭，传感器维持必要状态 | 无 | App/按键切换模式 |
| 聊天 | 半双工收音与语音播放；V1 默认按键发起，不要求常开唤醒 | 需要 Wi‑Fi 和云语音服务 | 用户结束、超时或切换模式 |
| 巡逻 | 低速循线；测距达到停车阈值即停止 | 本地运行；App 控制建议同一局域网 | 用户停止、路线丢失、障碍/故障、电量不足 |
| 看门 | 底盘停止；麦克风进行本地声音判定；满足条件后播放狗叫 | 报警不依赖网络；计划表需本地保存 | 用户撤防、切换模式或低电量故障 |

V1 看门设防方式为**App 手动设防/撤防 + 可选本地时间计划**。离家地理围栏自动设防属于后续需求，需额外评估 Android 后台定位权限、耗电和用户授权，不作为当前硬性承诺。

### 5.1 模式管理与控制

- **FR-01（P0）：模式切换。** 提供待机、聊天、巡逻、看门四种状态；任一时刻仅允许一个主要模式运行。切换前停止电机和当前音频任务，再启用新模式。
- **FR-02（P0）：急停。** 设备提供可触达的物理电源/电机停止手段；App 提供停止命令。远程手动驾驶时控制心跳中断、控制任务异常或模式切换时，电机默认进入停止状态；本地自治巡逻不依赖外网，遇到传感器/控制故障仍须停车。
- **FR-03（P0）：本地状态反馈。** 至少通过 App 页面或串口日志显示当前模式、Wi‑Fi 状态、电量估计/低电压状态、最近错误和看门报警次数。
- **FR-04（P1）：按时设防。** 支持配置每日开始与结束时间，计划保存在设备端；重启后恢复计划。时间未同步时不应悄悄进入错误设防状态。
- **FR-05（P1）：离家自动设防。** 后续可评估手机地理围栏；必须由用户显式授权并能手动撤销，不能仅依据网络断开判定用户离家。

### 5.2 固定路线巡逻与避障

- **FR-06（P0）：循线行驶。** 使用底部多路红外巡线传感器识别地面黑/白标线，执行左右轮差速控制。路线需由用户提前铺设；V1 不提供地图编辑器。
- **FR-07（P0）：障碍停车。** 使用前向 ToF 或等效测距传感器；距离低于可配置阈值时停止两侧电机并进入“受阻”状态。V1 优先安全停车，不要求绕过障碍。
- **FR-08（P0）：路线丢失保护。** 连续一段时间无法识别路线时停车并提示，不允许在不确定方向下持续行驶。
- **FR-09（P0）：限速与看门互锁。** 巡逻速度可配置但受固件上限约束；看门模式必须关闭电机，聊天播报期间暂停/抑制声音触发，减少自触发。
- **FR-10（P1）：巡逻状态提示。** 显示开始、运行、受阻、路线丢失、停止等状态；保存本次巡逻的开始/结束时间和停止原因。

### 5.3 看门声音检测与报警

- **FR-11（P0）：本地声音检测。** 在看门模式下从数字麦克风采样，估算短时声音能量；仅在阈值、持续时间和冷却条件同时满足时触发报警。
- **FR-12（P0）：本地狗叫。** 触发时从本地存储播放预置狗叫音频；报警播放不得依赖云端服务或联网。
- **FR-13（P0）：误报抑制。** 提供环境噪声基线/灵敏度档位、最短事件持续时间和报警冷却时间；狗叫播放期间屏蔽麦克风事件判定，播放结束后经过恢复间隔再监听。
- **FR-14（P0）：设防可见。** 设备或 App 明确显示“看门已设防/已撤防”；启动看门模式前提示设备需靠近入口放置，并说明声音检测不等于门外声源识别。
- **FR-15（P1）：事件记录。** 本地保留最近 N 条报警时间与触发强度摘要；V1 默认不保存原始音频，不上传连续环境录音。
- **FR-16（P1）：手机推送。** 仅在后续服务端与网络方案确定后实现；即使推送失败，本地狗叫也必须已执行。

### 5.4 语音聊天

- **FR-17（P0）：聊天发起。** V1 通过按键或 App 按住说话/点按录音开始，提供清楚的录音中、处理中、播放中和失败状态；不要求设备始终监听唤醒词。
- **FR-18（P0）：云端语音链路。** 服务端采用 ASR → LLM → TTS 级联流程；设备通过 Wi‑Fi 传输音频或压缩语音片段，并播放返回语音。各服务商应可配置替换，凭据仅存放服务端。
- **FR-19（P0）：半双工回声控制。** 播放 TTS 时暂停采音或不提交新输入；用户开始下一轮后恢复采音。首版不承诺免提全双工、低延迟插话或远场识别。
- **FR-20（P0）：失败处理。** Wi‑Fi、ASR、LLM 或 TTS 请求失败时，显示/播报简短失败提示、允许重试，并保持底盘处于安全停止状态；单次请求失败不得使主控重启。
- **FR-21（P1）：唤醒词。** 可评估 ESP-SR WakeNet 唤醒；唤醒词、麦克风位置、误唤醒率和内存占用通过原型验证后再纳入。

## 6. 关键交互流程

### 6.1 看门设防

1. 用户将机器狗放在玄关附近，确认其不会挡住通道或被门碰撞。
2. App/按键选择“看门”，选择立即设防或已保存的时间计划。
3. 设备确认底盘已停止、低电压未触发、麦克风与扬声器初始化成功。
4. 状态变为“看门已设防”；达到声音条件时本地播放狗叫，并按冷却规则记录一次事件。
5. 用户在 App 或设备端撤防；设备停止报警任务并恢复待机。

### 6.2 巡逻

1. 用户预先铺好闭合或端点明确的地面路线，并清除楼梯、易缠绕电缆等风险。
2. 用户启动巡逻；设备确认传感器可读、电池状态正常后低速启动。
3. 设备循线行驶；遇障立即停车并进入受阻状态。
4. 用户移除障碍并通过 App/按键恢复，或直接终止巡逻。
5. 路线丢失或传感器故障时设备停车并报告原因。

### 6.3 语音聊天

1. 用户按键/App 发起语音输入；设备提示正在录音。
2. 用户结束输入；设备上传到已配置的服务端。
3. 服务端返回语音后设备播放；播放期间暂停采音，避免扬声器回声。
4. 用户可开始下一轮、结束会话或切换模式。
5. 任一网络/服务环节失败时给出可重试错误提示，不影响看门本地逻辑或电机安全状态。

## 7. 硬件与系统约束

### 7.1 V1 候选硬件

| 子系统 | 候选规格/器件 | 需求与备注 |
|---|---|---|
| 主控 | ESP32-S3 N16R8 开发板 | Wi‑Fi、I²S 音频、GPIO 与电机 PWM；作为语音设备主控 |
| 底盘 | 2WD 双轮差速，含两台减速电机、车轮、支撑轮 | 以室内平地为主；编码器可选，首版循线不依赖高精度里程计 |

| 路线传感 | 5 路 TCRT5000 类巡线传感器 | 输出必须兼容 ESP32-S3 3.3V GPIO；如输出为 5V，需电平转换/分压方案 |
| 障碍传感 | VL53L0X 类前向 ToF 测距模块 | I²C 接口；按模块电气规格供电和接线 |
| 音频输入 | INMP441 类 I²S 数字麦克风 | 3.3V 逻辑/供电按模块规格确认；布置在机器狗头部或前上方 |
| 音频输出 | MAX98357A 类 I²S 功放 + 4Ω/3W 小喇叭 | 功放电源与扬声器阻抗按模块规格核对；音频播放时抑制麦克风自触发 |
| 电池 | 候选 2S 7.4V、2000mAh、40C 电池组 | “7.4V”为标称电压，满电约 8.4V；确认化学体系、电芯可信度、BMS/保护方式、放电能力和接口后再采购 |
| 电源转换 | 电机支路按电机额定电压选降压；逻辑与音频支路提供稳定电源；按实际电压拓扑配置各路稳压 | 先空载调压并用万用表确认，再接负载；电机电源不能接到逻辑 VCC |
| 电池电压采样 | 高阻分压接 ESP32-S3 ADC，或使用兼容电池化学体系的电压监测模块 | 若要提供低电压提示/停机，此项必需；分压电阻用直插件即可，阻值需按 ADC 最大输入电压计算 |
| 外壳 | FreeCAD 等自行建模，PLA 代打 | 打印非承重上盖、头部、传感器支架；优先复用金属/塑料底盘，预留通风、维修和电池拆装空间 |
| 调试/装配 | 400 孔面包板、杜邦线、洞洞板、用户按键、总开关、保险丝、线束及电池电压采样电阻 | 面包板仅桌面调试；车载连接改为焊接洞洞板/可靠插接；电机电流不得通过面包板；电池采样电阻不要求贴片封装 |
| 控制端（可选） | 已有的 Android 手机 | 运行 App 与控制界面；不计入硬件预算，见 Q-06 |

### 7.2 电气安全约束

- 电池、驱动板、电机和降压模块须按实际电压/电流规格匹配；2S 电池满电电压为 8.4V。
- TB6612FNG 的逻辑输入电源 VCC（常见 3.3–5V）与电机电源 VM 是不同接口；严禁把 2S 电池直接接到逻辑 VCC。东芝列出的 TB6612FNG 芯片输出规格约为每通道平均 1.2A、峰值 3.2A；峰值不能当作持续电流能力，模块板散热也会影响实际值。若商品页标注“2A/3.2A”，须核实该数字是连续/短时、单通道/整板。
- 最终电机驱动器按“两台电机各自的堵转电流和两侧同时启动”核算；若选用 4WD 或每侧电机并联，需重新评估驱动板、电池、线束和保险丝，当前 V1 不覆盖。
- 电池正极附近设置保险丝和实体总开关；软件通过电压采样实现低电压提示/停机，阈值须按最终电芯化学体系及每串电压要求确定。充电器必须与电池化学体系、串数、充电接口/平衡接口匹配。
- 若使用带 BMS 的 2S 成品电池组，BMS 持续放电电流可先以 ≥5A 作为筛选下限，最终须按两台电机的堵转/启动电流总和、主控与音频负载并留余量复核。若候选 40C 航模电池没有 BMS，则不存在可核对的“BMS 持续电流”参数，应核实电芯放电规格，并使用合适的低压保护和匹配的平衡充电器。
- 40C 是候选电池标称参数，不作为系统电流保证；若为无 BMS 航模 LiPo，须使用匹配的 2S 平衡充电器和低压保护，充电过程按电池供应商安全要求执行。
- 51 单片机套件可以作为底盘/电机驱动的候选来源，但不默认作为语音聊天主控。若购买套件，先确认是否已经包含驱动器、电机和电池盒，避免重复采购；ESP32-S3 与 51 板的职责需明确。若保留 51 板，ESP32-S3 是唯一电机命令源，不能让两块主控同时控制同一驱动输入；逻辑电平须确认兼容 3.3V GPIO。

## 8. 软件架构（已确定）

**基座选型：** 固件以开源项目 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)（MIT 许可证）为语音聊天基座，基于 **ESP-IDF v6.1**（不支持 5.x）构建；已注册自定义板卡 `ai-dog-s3`（ESP32-S3-N16R8 + INMP441 + MAX98357A，无屏幕），语音云端首选 xiaozhi.me 官方服务。

| 层 | 职责 | 实现接口/技术 |
|---|---|---|
| 语音聊天（已就绪） | 唤醒、音频编解码、ASR→LLM→TTS 流水线、云端会话 | xiaozhi-esp32；Opus + WebSocket/MQTT+UDP；离线唤醒词走 ESP-SR |
| 设备状态机 | 模式互斥（聊天/巡逻/看门）、错误恢复、低电量保护、看门计划 | ESP-IDF v6.1 自研任务；状态转换显式定义 |
| 运动控制 | TB6612FNG PWM、巡线传感、测距停车、软急停 | 电机驱动 GPIO/LEDC PWM；传感器 I²C/GPIO |
| 音频扩展 | 看门人模式声音触发狗叫（本地、断网可用） | INMP441 本地采样 + SPL 阈值检测；报警音本地存储/合成 |
| 网络控制 | 配网、设备状态、语音云端请求、MCP 设备控制 | xiaozhi 既有 WebSocket 通道；MCP 工具暴露电机/模式命令 |
| 语音服务端 | ASR、LLM、TTS 级联 | xiaozhi.me 云端；可迁移自建（xinnan-tech Python 版 / joey-zhou Java 版） |
| Android 控制端 | 模式设置、手动设防、巡逻启停、状态和事件查看 | Java Android App；V1 可先做最小控制界面 |

固件须采用"控制任务优先于聊天任务"的资源调度原则。语音网络请求和音频播放不能阻塞电机安全任务；网络/云服务故障时可独立保持本地状态机运行（看门检测与狗叫为纯本地逻辑，不依赖云端）。

## 9. 非功能需求

- **安全优先：** 电机控制异常、线路丢失、障碍、低电压、看门模式切换时默认停车。
- **断网韧性：** 看门检测及本地狗叫在 Wi‑Fi/云端不可用时仍有效；聊天在断网时明确失败并可重试。
- **可恢复性：** 单次传感器读取失败、云端请求超时或播放错误不能使系统崩溃；记录错误并进入安全状态。
- **可维护性：** 电机、音频、传感器、云服务配置分层，模块可单独替换；固件日志包含时间、模式、错误码，不输出密钥。
- **隐私：** 默认不保存或上传连续环境录音；语音聊天只上传用户主动发起的一轮；设置页说明云端处理范围和服务依赖。
- **可用性：** 设防状态、设备状态和故障原因对用户可见；用户能从 App 或实体开关快速停机。
- **供电：** 目标续航需经整机样机实测后确定，首轮验证目标为混合使用至少 30 分钟；续航数值不是未测试前的保证。
- **语音延迟基线：** 首版不设硬性端到端延迟门槛，但需按环节（VAD/ASR/LLM/TTS/播放）记录耗时中位数作为基线；后续优化目标为端到端 ≤800ms。首版以按键半双工实现，不追求全双工插话。
- **成本可控：** 采购前须按实际 SKU、运费和必需辅料复核总额；超 ¥500 须明确删项或重新审批（见 AT-10）。

## 10. 验收标准（V1）

## 12. 里程碑建议

1. **M0 物料确认：** 锁定底盘电机电压/堵转电流、驱动板连续电流、电池化学体系与充电方式；完成电源图和接口表。
2. **M1 供电与底盘：** 先验证降压、急停、单电机与双电机控制，完成限速、断联停车和低电压策略。
3. **M2 巡线避障：** 完成传感器标定、固定路线循线、障碍停车与丢线恢复；通过 AT-02、AT-03。
4. **M3 本地看门：** 完成声音能量判定、冷却、狗叫播放、设防/撤防和离线验证；通过 AT-04 至 AT-06。
5. **M4 云端聊天与 App：** 完成按键说话、服务端级联、TTS 播放、断网/超时处理和基本状态控制；通过 AT-07、AT-08。
6. **M5 结构与整机验收：** 根据真实器件尺寸完成狗形外壳，整理线束、验证温升和续航，完成全部验收与成本复核。
