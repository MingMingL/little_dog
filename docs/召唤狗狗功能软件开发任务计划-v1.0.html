Q-12测试用声源与验收口径？影响 AT-S04/S09 可复现性真人为主（AT-S04/S09），音箱放录音辅助（T3/T4）；另设"背景电视声/音乐"干扰组采纳M1

2. 开发策略与规范

  1. 分支：feature/summon-v15，每个 SW 任务一个 commit，信息带任务号（如 SW-102: 4-mic I2S capture backend (a)）。
  2. 编译开关：CONFIG_AI_DOG_ENABLE_SUMMON，默认 OFF——任何时刻都能构建出与 V1 行为一致的固件，召唤代码不影响 V1 验收。
  3. 参数化：方案 §4.3 全部参数进 Kconfig / config.h，禁止硬编码；标定后冻结值回写方案文档。
  4. 日志规范：TAG 用 summon / doa / mic_array / vision / line_i2c；每个决策点输出依据（DOA 角度、能量、子状态、与阈值的对比）——延续"输出完整 prompt"的调试习惯；不输出敏感信息。
  5. 代码落点与风格：全部落在 main/boards/ai-dog-s3/，沿用现有 ai_dog_* 单例 + 回调风格，与 ai_dog_control 状态机对接，不新增全局线程模型。
  6. 仿真先行：tools/sim_dog.py 先扩展为 Summon 状态机仿真，硬件未到也能验证抢占/超时/降级逻辑。

6. 与风险表的联动

开发中触发下列任一降级条件时，按最终实施方案 §7（R-F1~R-F10）执行，并在 SW-403 记录：

  • R-F1（自噪）→ SW-104 的 30% 占空比档 + SW-105 的 NSNet2 辅助；
  • R-F2（采集方式不顺）→ SW-102 后端切换；
  • R-F6（视觉不过）→ SW-303 关闭视觉、退回纯声学到达判定（AT-S04 口径）。
