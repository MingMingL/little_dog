# 电池监测与设备本地日志

> 2026-10-18 实现并在真机验证。解决的问题：**电池供电时反复重新初始化，但当时没有串口、看不到现场**。
> 现在掉电前的日志会存在板子自己的 flash 里，下次插串口自动打出来。

## 1. 三个能力

| 能力 | 位置 | 说明 |
|---|---|---|
| 设备本地日志 | `main/boards/ai-dog-s3/ai_dog_diag.cc` | esp_log 钩子 → 内存环 → `doglog` 分区，掉电不丢；下次启动自动 dump 到串口 |
| 复位原因 | 同上 | `esp_reset_reason()` 中文映射，启动时打印；**brownout 会单独告警** |
| 电池监测 | `main/boards/ai-dog-s3/ai_dog_battery.cc` | GPIO8 / ADC1_CH7 + 电阻分压，出电压和百分比，四档保护 |

## 2. 设备本地日志怎么用

**什么都不用做。** 插上串口打开监视器就行 —— `idf_monitor` 启动时会复位芯片，复位后第一件事就是把上次的记录打出来：

```bash
python build-ai-dog.py monitor -p COM4
```

```
===== 设备本地日志（上次掉电前，239 条） =====
[I      0.654] I (824) wifi: state: init -> auth (0xb0)
[I      1.941] I (2114) esp_netif_handlers: sta ip: 192.168.0.103, ...
===== 设备本地日志结束 =====
W (1479) DeviceLog: 本次启动：复位原因 = POWERON (1) 正常上电
```

> 注意：`rst:0x...` 那一行是 **ROM 在 C 代码之前**打的，钩子抓不到，所以只有实时开着串口才看得见。
> 软件侧的等价信息就是上面那行 `DeviceLog: 本次启动：复位原因 = ...`，已经落盘，掉电也丢不了。

### 排查"电池供电反复重启"看什么

| 复位原因 | 含义 | 下一步 |
|---|---|---|
| `BROWNOUT (9)` 掉压复位 | **实锤供电问题** | 量 5V 轨，查 MP1584 输入是否 ≥6.5V，看 `docs/硬件接线方案-v7.html` 供电段 |
| `POWERON (1)` | 真的断电/开关接触不良 | 查电池开关、导线、端子 |
| `PANIC (4)` / `TASK_WDT (6)` | 程序问题，与供电无关 | 抓 Guru Meditation 全文 |
| `PWR_GLITCH (14)` 电源毛刺 | 瞬时跌落 | 加大 ESP32 5V 针附近的储能电容 |

## 3. 电池监测：分压比标定（**必须先做**）

当前固件按 `DOG_BATTERY_DIVIDER = 3.0` 计算（`config.h`）。**这个值必须和实际电阻对上**，否则电压是错的。

标定三步：

1. 万用表量 2S 电池整组真实电压 `Vbat`；
2. 看启动日志里这行的 `adc raw`：
   ```
   W (1509) AiDogBattery: 电池读数 1.51V 不在合理区间 [5.5, 9.6]，按未接分压处理；adc raw=505mV
   ```
   这里的 `505mV` 就是 GPIO8 引脚上测到的电压 `Vadc`；
3. 分压比 = `Vbat / Vadc`，填回 `config.h` 的 `DOG_BATTERY_DIVIDER`，重新编译烧录。

**读数不在 5.5–9.6V 区间时一律按"未接分压"处理**：`/api/status` 报 `battery_volts: -1`、
`battery_level: "unknown"`，并且**不做任何保护动作**。这是故意的 —— 分压没接好时 ADC 悬空读数乱跳，
不能让它把狗误关机。所以没标定之前，狗不会因为电池逻辑自己关机。

心跳日志每 30 秒一条（电压没变也打），电池测试时用来看趋势。

## 4. 四档保护与门限

门限都在 `config.h`，2S 锂电（满 8.4V / 标称 7.4V）：

| 档位 | 门限 | 动作 |
|---|---|---|
| `Normal` | > 6.9V | 无 |
| `Warn` | ≤ 6.9V | 日志 W + OLED 提示 + `/api/status` 的 `fault` 置"电池电压低" |
| `Restrict` | ≤ 6.6V | 上面全部 + **拒绝切入巡逻/看门/遥控** + 立即急停 |
| `Cutoff` | ≤ 6.3V | 停电机 + 日志 E + **先落盘再深度睡眠** |

- `Restrict`/`Cutoff` 需要**连续 3 次**（2 秒一次，共 6 秒）都读低才认，防 ADC 抖动误关机；
  回到 `Normal`/`Warn` 立即生效。
- MP1584 要稳定输出 5V，输入至少 ~6.5V，所以门限压在 6.5V 以下 —— 赶在 5V 轨崩掉之前动作，
  而不是等 brownout 把芯片打重启。
- `Cutoff` 里 `diag.Flush()` 在 `esp_deep_sleep_start()` **之前**，否则最后几条白记。

## 5. `/api/status` 新增字段

```json
{
  "battery": -1,              // 百分比，-1 = 读不到
  "battery_volts": -1,        // 实测电压（V），-1 = 读不到
  "battery_level": "unknown", // normal/warn/restrict/cutoff/unknown
  "fault": null
}
```

`POST /api/mode` 在电量受限时会返回 `{"ok":false,"error":"mode change rejected ..."}`。

## 6. 分区表变动（**必须重新烧分区表**）

`partitions/v2/16m.csv`：`assets` 8M → 2M，新增 `doglog`（64KB @ `0xA00000`）。

```
nvs      16K  0x009000      otadata   8K  0x00D000
phy_init  4K  0x00F000      ota_0   4032K 0x020000
ota_1   4032K 0x410000      assets  2048K 0x800000
doglog    64K 0xA00000
```

- 当前 `assets.bin` 约 0.56M，2M 仍有 3 倍余量；`build_default_assets.py` 带 `--max_size`，超了直接报错。
- `ota_0`/`ota_1` 位置未变，**只烧 app 不烧分区表时 `doglog` 不存在**，此时 DeviceLog 自动退化成
  "仅串口、不持久化"并打一条警告，不会崩。
- 重新烧录用 `python build-ai-dog.py flash -p COM4`，esptool 默认会带上 `partition-table.bin`。

## 7. 存储格式与掉电安全

`doglog` 是 256 字节定长记录的环形缓冲，64KB / 256B = 256 条：

```
[0..3]   magic 'DLOG'        [4..7]   序号（单调递增，跨重启不清零）
[8..11]  写入时 uptime(ms)   [12]     级别 0=I 1=W 2=E
[13]     写入时复位原因      [16..255] 文本
```

- 每条写入前保证所在 4K 扇区已擦净（`esp_partition_erase_range`）；
- 启动时扫描全部有效记录，**按序号排序**后打印 —— 所以环形覆盖过也能按时间顺序看；
- 掉电写在半条记录上 → magic 不完整 → 扫描时跳过，不会读到乱码；
- esp_log 钩子里只做内存拷贝（微秒级），擦除+写 flash 都在独立的 `doglog` 任务里，
  而且 `xPortInIsrContext()` 时直接跳过（中断里不能做 flash 操作）。

## 8. 磨损与调参

日志全量落盘，flash 按 10 万次擦写算，256 条环形 ≈ 2560 万条日志的寿命；
本机空闲时约 1–2 条/秒，按这个速率够跑几年。要更保守可以调 `ai_dog_diag.cc` 里
`FlushTask` 的轮询周期（默认 2 秒）。

要改的门限集中在 `main/boards/ai-dog-s3/config.h`：

```c
#define DOG_BATTERY_DIVIDER        3.0f   // 分压比，先标定！
#define DOG_BATTERY_VALID_MIN_V    5.5f   // 合理区间下限
#define DOG_BATTERY_VALID_MAX_V    9.6f   // 合理区间上限
#define DOG_BATTERY_WARN_V         6.9f
#define DOG_BATTERY_RESTRICT_V     6.6f
#define DOG_BATTERY_CUTOFF_V       6.3f
```
